구현 중에 만난 문제와 해결 과정. 각 항목은 상황, 원인, 해결, 확인 방법 순서로 적는다.

## 2026-11-17 · 사용자가 파이프라인 코멘트를 지우면 그 PR의 작업이 전부 멈출 뻔함 (1단계)

**상황.** 파이프라인은 PR당 코멘트 하나를 달고, 다음 커밋부터는 SQLite `runs`에 저장한 코멘트 ID로 같은 코멘트를 고친다 (DESIGN.md F9). 기능 요구사항에는 "사용자가 그 코멘트를 지우는 경우"가 없었다.

**원인.** 코멘트가 지워지면 저장된 ID로 보내는 수정 요청(`PATCH /issues/comments/{id}`)이 404를 돌려준다. gh 호출 실패는 환경 오류로 다뤄지므로 작업은 재시도 3회 뒤 실패하고, 다음 커밋의 작업도 `runs`에서 같은 지워진 ID를 꺼내 똑같이 실패한다. 결과적으로 그 PR에는 다시는 결과가 달리지 않는다. 작업 범위 판단 기준의 "작업이 멈춤"에 해당한다.

**해결.** `worker/github.py`의 `upsert_comment`에서 수정 요청이 404면 저장된 ID를 버리고, 파이프라인 표시(`<!-- pr-proof -->`)와 작성자로 코멘트를 다시 찾고, 없으면 새로 단다. 404가 아닌 실패(인증 만료 등)는 그대로 올려 환경 오류로 처리한다.

**확인.** `tests/worker/test_github.py`
- `test_deleted_comment_falls_back_to_create`: 수정 404 → 다시 찾기 → 새로 달기 순서로 호출됨
- `test_other_patch_errors_propagate`: 401은 숨기지 않고 올라감
- `test_finds_own_marked_comment`: 다른 사람이 표시를 흉내 낸 코멘트는 건너뜀

**배운 점.** 파이프라인이 GitHub에 남긴 것은 사람이 언제든 지우거나 바꿀 수 있다. 저장해 둔 외부 리소스 ID는 "없을 수 있음"을 정상 경로로 다뤄야 한다.

## 2026-11-19 확인 대상(code·pr·human) 고르기 (완료 기준 1a-4)

**왜.** MathLLM README에는 코드 규칙, PR 규칙(브랜치, 커밋 메시지), 사람의 절차(데이터 누수 확인, PR 체크리스트)가 한 문서에 섞여 있다. 절을 설정으로 지정하게 하지 않고, 규칙 읽기에서 모델이 규칙마다 무엇을 보고 확인하는 규칙인지 고르게 했다. `code`만 검사하고 `pr`과 `human`은 코멘트에 목록으로만 보인다.

**방법.** MathLLM `origin/main`(57edb48)의 README와 eval의 README를 실제 모델로 읽었다. MathLLM은 sonnet 3번, haiku 3번, eval은 한 번씩. 규칙 읽기만 돌렸고 PR이나 코멘트는 만들지 않았다.

- 코드 규칙 7개(README의 "코드 규칙" 1~7번)는 6번 모두 `code`였다. 파일 이름 규칙(`build_<대상>.py`)도 `code`다.

## 2026-11-19 경로 패턴 검사기와 범위 추정의 효과 확인 (완료 기준 1a-1 ~ 1a-3)

**왜.** 파일 이름 규칙("테스트 파일 이름은 `test_<모듈>.py`다")은 코드 예시로 가릴 수 없어 검사하지 못하거나 뜻이 어긋난 검사기로 남았다. 범위 추정은 glob의 모양만 보고 받아서 `**/test_*.py` 같은 좁히는 glob을 버렸다.

**경로 패턴 검사기.** 규칙 읽기가 경로 규칙에 힌트(`check: path`)를 달고, 그 규칙은 선언(JSON: `applies_to`, `condition`, `pattern`)과 경로 예시로 검사기를 얻는다. 선언은 파이프라인의 고정 스크립트가 샌드박스에서 경로에 맞춘다. PR이 새로 만든 파일만 보고 위반은 파일 단위다.

- 실제 모델 확인: eval `main`(2070aa1) 위에 `tests/pricing_test.py`와 `tests/test_fee.py`를 더한 로컬 커밋(push하지 않음)으로 규칙 읽기 → 검사기 작성 → 위반 찾기를 haiku로 돌렸다. 테스트 파일 이름 규칙(`R-readme-4be42e5f`)이 1회차에 `path-pattern` 검사기 `08902946`을 얻었고, `tests/pricing_test.py`만 "(파일 이름·경로)" 위반으로 나왔다. `tests/test_fee.py`는 나오지 않았다.
- 모델이 쓴 선언: `applies_to: ^tests/(?!.*(__init__|conftest)\.py$)`, `must_match`, `pattern: (^|/)test_[^/]+\.py$`.
- 끝없이 되짚는 정규식(`^(a+)+$`)은 샌드박스의 시간 제한에서 멈춘다 (`pytest -m docker`).
- 기존 검사기의 캐시 키는 그대로다(경로 패턴의 프롬프트 버전을 따로 센다). 규칙 읽기는 프롬프트가 바뀌어 저장소마다 한 번 다시 읽는다.
